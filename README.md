# BioCraft · 生物工艺

> 硬核生物化学科技模组 | Minecraft 1.21.1 / NeoForge | 将真实的代谢通路、中心法则、酶动力学完整且有创意地搬进 Minecraft

## 创意与设想

### 设计理念：科学性是基石，游戏性是纽带

本模组的第一准则是尽可能忠实于生物化学与分子生物学的真实原理。游戏性是连接玩家与科学的桥梁，但桥梁不能扭曲基石的形状。

**你操作的将不再是"粉"与"锭"，而是分子。**

堆叠数 = 分子个数：1 个葡萄糖分子（C₆H₁₂O₆）就是 6 个碳原子 + 12 个氢原子 + 6 个氧原子，严格化学计量。玩家的仓库，就是一台活的分子计数器。

### 这个模组不是什么

- 不是"套皮科技模组"——不是把熔炉逻辑用生化名词重写一遍
- 没有 FE / Forge Energy 驱动的机器——能量是 ATP 分子，是**物品物流**，不是电线
- 没有原版风格的机器合成配方——**酶工厂由 `enzymes.json` 数据表解析创建**，每个工厂是一个化学热力学 + 动力学反应模拟器；中心法则信息层（序列机家族）为独立的信息传递体系，与化学引擎分工：化学引擎管速率与平衡，信息层管序列传递（离散逐位步进，保留化学计量）
- 没有 MK2/MK3 升级阶级、没有物理多方块结构——升级靠"酶插件"，细胞器靠相邻检测

### 核心玩法闭环

> 经中心法则（信息层第一波已落地：seq 引擎 + DNA 编码器/转录仪；翻译/折叠等后续）产出酶蛋白 → 插入酶反应腔成为功能性机器 → 搭建代谢流水线（糖酵解/发酵/TCA/ETC）产出更多 ATP → 用 ATP 驱动更复杂的合成与升级 → 最终实现物质与能量的自循环

### 三大体系

| 体系 | 内容 |
|---|---|
| **能量体系** | ATP 是唯一"通用货币"。机器以 ATP 分子驱动，产出 ADP 副产物；玩家必须设计 ADP→ATP 回收循环，否则产线堵塞。ATP 合酶发电机可将化学势能转化为 FE 供其他模组使用（已实现：ATP 水解酶） |
| **氧化还原体系** | NAD⁺/NADH 循环：脱氢酶消耗 NAD⁺ 产出 NADH，NADH 回收再生 NAD⁺（已实现：GAPDH 消耗 / LDH、ADH 再生）；未来电子传递链大量产 ATP |
| **中心法则** | 模组的"信息工厂"（第一波已落地）：central 信息引擎 + DNA 编码器/转录仪已实现，解旋/复制/翻译/装载/折叠/试剂盒待开发。玩家写程序文本 → 编码成 DNA → 转录 mRNA → 未来翻译/折叠产出酶蛋白，插入酶反应腔即成为功能性机器 |

### 酶动力学：纯米氏方程 + 化学热力学模拟

- 每个酶工厂是一台独立的化学反应模拟器：多底物米氏方程（Km/kcat/共享分母）、化学热力学（Keq 判决点、Haldane 逆向 Vmax、产物回压、饱和有界）
- 机器行为完全由引擎计算，GUI 统一展示 v-t 通量折线图、平衡区（log(Q/Keq)）与实时速率读数
- 温度影响待实现（引擎温度修正已就绪，外部温度源未接入）

### 模组架构：酶工厂 + 分子

| 部分 | 内容 |
|---|---|
| **酶工厂** | 负责生物化学分子的反应（合成代谢与分解代谢），是模组的"工厂"；由 `enzymes.json` 数据表解析创建，接受分子输入、按热力学与动力学计算反应、输出产物与副产物 |
| **分子** | 工厂处理的物质：物品即分子/原子/离子，堆叠数 = 分子个数，严格化学计量比 |

**模组核心 = 建立不同逻辑的工厂**：通过数据表定义反应网络（糖酵解、发酵、TCA、ETC……），玩家搭建工厂流水线，实现完整的生物代谢循环（ATP/ADP、NAD⁺/NADH、H⁺、能量 FE 的回收与闭环）。

**最终目标 = 细胞工厂**：以酶工厂网络模拟完整细胞代谢，实现近乎创造模式的全物质合成，且完全依赖生化产线供能。

**远期目标：蛋白质工程与人工代谢系统**

BioCraft 的终局不只是"生产出所有天然酶"，而是让玩家能够通过 DNA→蛋白质→酶性质→反应网络这一完整链条，自主设计和优化人工生物系统。

设计原则：

- **信息层真实，性质层抽象**：中心法则保留真实的序列信息传递（DNA→mRNA→氨基酸序列），但酶的催化性质（kcat/Km/稳定性/特异性）由游戏化的蛋白质性质模型决定，不要求真实蛋白质结构预测
- **酶不能凭空改变 Keq**：蛋白质工程改变的是活化能（催化效率），而非反应自由能（热力学平衡位置）。改变反应方向的正确方式是反应偶联——用强驱动力反应拉动弱反应
- **不存在绝对最优酶**：kcat 提高可能伴随 Km 变大或稳定性下降，玩家必须根据自身代谢系统选择最合适的酶变体

开发阶段规划：

- **Phase 1 中心法则基础设施**：DNA 序列 DataComponent、DNA 编码器（程序文本 → 程序 DNA）、转录、翻译（密码子表 + tRNA 体系：1 通用 tRNA + N 种 aa-tRNA + N 种专一 ARS）、蛋白质折叠，全链条真实可运行
- **Phase 2 蛋白质身份系统**：统一 Protein 数据结构（氨基酸序列/折叠状态/催化性质），DNA→蛋白质真正产出蛋白质物品
- **Phase 3 蛋白质性质模型**：游戏化的 kcat/Km/稳定性/底物特异性模型，同序列同性质、微小突变性质可能改变、trade-off 约束
- **Phase 4 酶工程**：DNA 突变、定点突变、蛋白质变体、WT/工程酶对比，玩家开始真正的蛋白质工程
- **Phase 5 反应网络工程**：多反应网络、中间体共享、竞争反应、分支/汇合/旁路，从单步反应升级到代谢路径设计
- **Phase 6 反应偶联**：ATP/GTP/NADH 水解偶联、总体 ΔG/Keq 计算、用偶联系统将不利反应拉向目标方向
- **Phase 7 代谢工程**：自定义代谢路径、旁路设计、ATP 成本优化、产率/通量/稳定性多目标优化，最终建立玩家自己的人工细胞

### #1 Pipez 能量管道无法从 ATP 水解酶抽出能量（2026-08-15 登记）

**现象**：ATPase 能量已满（Jade 确认能量槽存在且满），Pipez 能量管道设为抽出模式后仍无法抽走能量；Mekanism 线缆 PULL 模式可正常抽出（抽出速率与引擎工作速度相关）。

**根因分析**（反编译 Pipez 1.2.31 字节码确认）：
- Pipez 能量管道内部无能量缓存（`PipeEnergyStorage.getEnergyStored()` 恒 0），采用"每 tick 直通拉取"模型：`PipeEnergyStorage.tick()` → `EnergyPipeType.pullEnergy()` → 从源 extract → 直接推给目标
- 但拉取器 `energyStorages[方向]` 是**懒创建**：只在外部方块查询**管道 BE 自身**的 EnergyStorage capability 时创建（`onRegisterCapability`）；创建前 `tick()` 中 `ifnull` 直接跳过 → 拉取逻辑从未启动
- 本场景 ATPase（被动拉取方）与 Trash Cans 垃圾桶（被动接收方）均不查询管道 capability → 拉取器恒 null → 永不拉取

**排除项**（已实测/反编译验证）：
- 本 mod 的 `IEnergyStorage` 实现正确（Mekanism PULL 模式抽出成功、Jade 读得到能量）
- Pipez 的 `isExtracting`/`shouldWork`/`canExtract`/`getExtractingConnection`/`getSortedConnections`/`insertOrdered` 链路均无问题
- 能量变化时本 mod 已调用 `invalidateCapabilities()` 通知 capability 缓存刷新

**搁置原因**：属 Pipez 自身"被动网络不启动拉取"的机制问题，本 mod 无代码修复空间；验证动作（Jade 对准管道触发懒创建）待用户复测。

**规避方案**：能量传输使用 Mekanism 线缆 + PULL 模式（已实测可用）；Pipez 保留用于物品/流体管道。
