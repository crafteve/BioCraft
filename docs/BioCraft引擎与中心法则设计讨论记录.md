# BioCraft 引擎演进与中心法则设计讨论记录

> 讨论日期：2026-08-17 ~ 2026-08-18
> 参与者：项目作者 + AI 辅助设计

---

## 一、项目背景

### 1.1 BioCraft 是什么

BioCraft（生物工艺）是一个 Minecraft 1.21.1 硬核生物化学科技模组。

和传统科技模组（Mekanism、Thermal Expansion、GregTech）不同，BioCraft 不做"矿石→粉→锭→机器"的套路，而是把真实的生物化学搬进 Minecraft：

- **物品 = 分子**：1 个葡萄糖物品 = C₆H₁₂O₆，堆叠数 = 分子个数，严格化学计量
- **能量 = ATP 分子**：不是 FE/RF 电线，而是 ATP 物品通过漏斗/管道物理搬运到机器
- **机器 = 酶反应腔**：唯一一种方块，放入不同酶蛋白物品 = 不同的化学反应
- **反应 = 米氏方程模拟**：不是固定配方表，而是真实的酶动力学 + 化学热力学（Keq、Km、kcat、产物回压、温度修正）

核心理念：**科学性是基石，游戏性是纽带。**

### 1.2 当前进度

模组已完成的部分：

**物品地基**：66 个分子物品（20 种氨基酸、13 种离子、5 种原子、2 种无机物、5 种碱基、4 种 NTP、3 种辅酶、14 种糖酵解/发酵中间体），全部由 `substances.json` 数据表驱动注册。

**化学引擎**：纯 Java 内核（零 MC 依赖），多底物可逆米氏方程 + Rosenbrock-W 半隐式积分器，28 个单测用例全绿。刚性场景（如 TPI kcat=9000）比旧 RK4 快 17~20 倍。

**酶反应腔**：14 个独立酶工厂方块已合并为唯一 `enzyme_chamber`。0 槽放入酶蛋白物品（堆叠数 = 酶浓度 [E]），BE 动态解析酶种构建引擎模拟器。完整 GUI（v-t 通量图、平衡区、速率读数、IO 模式）、JEI 配方、工业 IO 管道接入。

**糖酵解 + 乳酸发酵**：14 步酶数据齐全（HK/PGI/PFK/ALDO/TPI/GAPDH/PGK/PGM/ENO/PK + LDH/PDC/ADH/ATPase），Km/kcat/Keq/ΔH 数值溯源自 eQuilibrator 和 BRENDA 数据库。

**待开发**：中心法则链、糖酵解流水线搭建、温度机制、细胞器。

## 二、讨论的问题背景

### 2.1 引擎架构问题

在开发过程中发现了一个根本性问题：**化学引擎在处理高刚性系统时数值不稳定**。

典型场景：TPI（磷酸丙糖异构酶）kcat=9000，当酶堆叠 64 个时，系统特征时间尺度极短（~0.0001 秒），而 Minecraft 的 tick 间隔是 0.05 秒。用显式积分器（RK4）在大步长下会数值震荡——通量显示巨大但浓度几乎不动，表现为"机器在跑但不出东西"。

这个问题通过四层启发式判据 + 最多 64 子步细分解决过，但代码复杂、调参困难、有边界 case。

### 2.2 中心法则的设计方向问题

模组的终极目标是"细胞工厂"——用酶反应网络模拟完整细胞代谢。但目前酶蛋白物品的来源是一个未解决的问题：**没有中心法则，怎么合成酶？没有酶，怎么搭建中心法则？**

这就是"先有鸡还是先有蛋"的问题。

现有的酶蛋白物品是通过 `enzymes.json` 数据表直接注册的（相当于"凭空出现"），但设计目标是让酶蛋白通过中心法则链（DNA→mRNA→蛋白质）在游戏内生产出来。

### 2.3 中心法则与酶反应腔的本质区别

讨论中逐步明确了两个系统的根本差异：

**酶反应腔**是化学反应模拟器——底物在酶的催化下转化为产物，遵循米氏方程动力学，有平衡问题（Keq），有可逆反应。它关心的是浓度、通量、平衡位置。

**中心法则**是信息流处理器——DNA 的碱基序列决定 mRNA 的序列，mRNA 的密码子决定蛋白质的氨基酸序列。它关心的是模板读到第几个碱基、当前密码子是什么、对应的氨基酸是哪个。

这是两种完全不同的计算模式。把它们硬塞进同一个方块实体（BE）会导致代码臃肿、GUI 对不上、职责混乱。

## 三、讨论成果

### 3.1 引擎方向：从"精确求解"到"游戏化行为"

经过对 RK4、Rosenbrock、BDF、隐式 Euler 等多种数值方法的对比分析，以及对"连续 ODE 在离散 tick 网格上求解"这一根本矛盾的讨论，最终达成了一个关键共识：

**这个模组不需要精确求解生化 ODE，而是需要"游戏化的行为表现"。**

也就是说，引擎的目标不是精确模拟每一个分子的运动轨迹，而是让玩家看到正确的定性行为：饱和效应、平衡趋近、产物回压、酶浓度线性加速、温度影响。

在此基础上，评估了三种方案：

| 方案 | 精度 | 复杂度 | 刚性处理 | 结论 |
|------|------|--------|----------|------|
| RK4 + 补丁 | 中等 | 高（416行+4判据） | 已解决但复杂 | 维护成本高 |
| Rosenbrock-W | 高 | 中（~200行） | 原生处理刚性 | 已采用，性能好 |
| 直接进度法 | 一阶近似 | 低（~80行） | 无刚性问题 | 游戏化方向的候选 |

最终采用了 **Rosenbrock-W 半隐式积分器**（KPP ROS-4 系数，4 阶 L-stable），大步长直接处理刚性系统，比旧 RK4 快 17~20 倍。

同时讨论了更激进的"精确稳态 + 指数弛豫"方案——对于单底物可逆反应有解析解 `S(t) = A − B × exp(−r × t)`，一步到位不需要积分。但多底物反应没有通用解析解，最终没有替换 Rosenbrock。

### 3.2 中心法则的设计方向

#### 先有鸡还是先有蛋

讨论确定了渐进解锁的方案：

```
阶段 0：世界获取
  玩家在地下发现"远古细胞遗迹"结构
  → 获得几种预编码的 DNA 模板碎片
  → 获得少量"原始翻译因子"（一次性催化剂）

阶段 1：中心法则初阶
  用 DNA 组装器（无催化剂可运行，慢）
  → 从碎片拼装完整 DNA 模板
  用转录仪（需要 RNA 聚合酶，阶段 0 产出的）
  → 从 DNA 转录出 mRNA
  用翻译仪（需要核糖体因子，阶段 0 产出的）
  → 从 mRNA 翻译出第一批酶蛋白

阶段 2：正反馈循环
  第一批酶蛋白（如 RNA 聚合酶）→ 加速转录
  → 更多 mRNA → 更多翻译 → 更多酶蛋白
  → 可以生产所有 14 种酶蛋白

阶段 3：完整细胞
  代谢网络（糖酵解/TCA/ETC）全部运转
  → ATP/NADH 循环建立
  → 中心法则 + 代谢 = 自我维持
```

#### 中心法则的本质：真正的酶，但不同的反应机制

这是讨论中最重要的设计决策之一：

**中心法则的每一步都是真实的生物酶催化的反应。** DNA 聚合酶、RNA 聚合酶、核糖体——这些都是真正的酶，和己糖激酶、乳酸脱氢酶一样，作为酶蛋白物品插入 Enzyme Chamber。

但它们催化的"反应"与代谢反应有本质区别：

| | 代谢反应（现有） | 中心法则反应（新） |
|---|---|---|
| 本质 | 化学平衡 | 信息复制/传递 |
| 可逆性 | 可逆（Keq 决定平衡） | 基本不可逆 |
| 产物决定因素 | 底物浓度 × 酶动力学 | 模板序列 + 底物供应 |
| 配方 | 固定化学计量比 | 序列依赖——模板决定产物序列 |
| 平衡问题 | 有 | 无 |

#### 中心法则机器链（微观生物工厂）

最终确定的方案是建立一套**独立的方块/BE/GUI**（不复用现有 EnzymeFactoryBlockEntity），但复用"酶蛋白物品作为催化剂"的机制。

因为现有 BE 本质上是一条产线控制器，关心浓度、通量、平衡、v-t 图。而中心法则机器需要完全不同的信息：模板读到第几个碱基了、当前密码子是什么、对应的氨基酸是哪个、肽链长到什么程度了。GUI 也完全不同——玩家想看的是"DNA 转录到哪了"，而不是浓度条。

确定的机器链：

| # | 机器 | 输入 | 输出 | 催化剂 | 生物学对应 |
|---|---|---|---|---|---|
| 1 | DNA 组装器 | DNA 碎片 + dNTP | 完整 DNA 模板 | DNA 聚合酶 | DNA 复制 |
| 2 | 转录仪 | DNA 模板 + NTP | mRNA 链 | RNA 聚合酶 | 转录 |
| 3 | 翻译仪 | mRNA + 氨基酸 + tRNA + GTP | 多肽链 | 核糖体 | 翻译 |
| 4 | 折叠仪 | 多肽链 + ATP | 折叠蛋白 | 分子伴侣 | 蛋白质折叠 |

每一步都是酶催化的反应，与代谢反应同构（酶蛋白物品作为催化剂），但 BE 和 GUI 是独立实现的。

#### 序列依赖的特殊处理

中心法则反应中，产物的序列取决于输入的模板序列。处理方案是分层：

**化学计量层**（仍由引擎处理）：底物消耗速率（kcat × [E] × 饱和度）、能量消耗（ATP/GTP）、催化剂影响。这部分与代谢反应相同。

**序列逻辑层**（在 BE 层实现，不在引擎里）：转录时读 DNA 碱基、按互补规则产出 mRNA；翻译时读 mRNA 密码子、查密码子表、选择对应 tRNA。序列数据存储在物品的 DataComponent 上。

#### tRNA 的设计

讨论确定了 20 种 tRNA 作为 20 种不同物品（而非 1 种物品不同 NBT），原因：

1. 20 种 tRNA 本身就是生物学的真实细节
2. 玩家需要为每种 tRNA 搭建充电线（氨基酰 tRNA 合成酶 × 20）
3. 翻译仪的槽位需要"哪种 tRNA 有足够的"这个信息，20 种物品比 1 种物品的 20 个 NBT 更直观
4. JEI 里 20 种 tRNA 各有各的合成配方，信息清晰

#### 蛋白质折叠

讨论确定了折叠单独做一个方块（不内置到翻译仪），原因：

1. 折叠是真实的独立步骤，有专门的酶（分子伴侣如 GroEL/ES）
2. 增加了一个有意义的中间产物（多肽链 vs 折叠蛋白）
3. 未来可以扩展"蛋白质修饰"（磷酸化、糖基化等）

## 四、待决定的问题

以下问题在讨论中提出了但尚未最终决定：

1. **DNA 组装器怎么处理碎片拼装？** 是序列对齐（找到重叠区域拼接）？还是简单拼接（按顺序连接）？还是需要玩家手动排列碎片顺序？

2. **一个 DNA 模板能编码多种蛋白质吗？** 生物学上一个 operon 可以编码多个蛋白质，但这会增加复杂度。简化方案：一个 DNA 模板 = 一种蛋白质。

3. **蛋白质修饰要做进去吗？** 磷酸化、糖基化、二硫键等，还是折叠后直接产出成熟酶蛋白？

4. **翻译仪的粒度？** 每 tick 处理一个密码子（细粒度，能看到进度）？还是每 tick 处理一段（粗粒度，但更接近"配方工厂"）？

5. **中心法则产物的多样性？** 只产出 enzymes.json 里已有的 14 种酶蛋白？还是可以产出任意蛋白质（由 DNA 序列决定）？

6. **中心法则机器的 GUI 设计？** 需要展示序列可视化、密码子表对照、tRNA 匹配状态、肽链生长动画等，具体布局需要设计。

## 五、设计哲学总结

### 引擎层面

- **从"精确求解"转向"游戏化行为"**：不追求 ODE 的精确数值解，而是追求玩家能感知的正确行为（饱和、平衡、回压、酶加速）
- **Rosenbrock-W 已足够好**：处理了刚性问题，性能足够，不需要更复杂的方案
- **解析解只在特殊情况下有意义**：单底物可逆反应有精确解，但多底物反应没有通用解析解

### 中心法则层面

- **每一步都是真实的酶**：DNA 聚合酶、RNA 聚合酶、核糖体都是酶蛋白物品，与代谢酶同构
- **但实现方式不同**：中心法则需要独立的方块/BE/GUI，因为信息流处理与化学平衡模拟是完全不同的计算模式
- **序列信息通过物品 DataComponent 传递**：模板的序列决定产物的序列，这是中心法则与代谢反应的根本区别
- **酶反应腔是"产线"，中心法则机器是"蛋白质工厂"**：前者追求效率和通量，后者追求多样性和信息准确性
- **两个系统通过酶蛋白物品连接**：中心法则的最终产物 = 酶反应腔的催化剂

### 整体架构

```
世界探索 → 获得 DNA 碎片 + 种子催化剂
    ↓
中心法则机器（DNA 组装 → 转录 → 翻译 → 折叠）
    ↓ 产出酶蛋白物品
酶反应腔（糖酵解 / 发酵 / TCA / ETC）
    ↓ 产出 ATP + 代谢分子
ATP 驱动更多中心法则反应
    ↓
正反馈循环 → 完整细胞工厂
```
